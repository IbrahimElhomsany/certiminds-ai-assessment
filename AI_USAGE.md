## 4. AI-generated code that was accepted
- Deterministic tools (`backend/tools.py`) with Decimal arithmetic and the full-box pricing basis.
- Gateway with retries, exponential backoff, fallback, structured-output validation, cache, metrics.
- RAG pipeline with hybrid BM25 + embeddings and quarantine of malicious documents.
- Sales agent with Claude tool use, deterministic fallback mode and output guardrails.
- Evaluation framework (36 cases) and the baseline-vs-adapted comparison script.

## 5. AI-generated code that was rejected or changed
Changes made after running the code and checking the results:
- The first recommender ranked **Arctic Pearl (R9, polished)** third for a busy restaurant floor. A hard rule was added: high-traffic commercial floors need slip R10 or above.
- The word "budget" in "Budget is roughly $1,000" was wrongly treated as "the customer wants the cheapest option". It was removed from the price-sensitivity keywords.
- "I need tiles for my new home" didn't ask which room the tiles were for. The missing-information logic was changed to always ask for the application.
- Arabic application names (e.g. شرفة) were mapped to English values so the rules apply.
- A planned dense-embedding-only RAG was changed to **hybrid with a BM25 fallback**, because the embedding model download couldn't be guaranteed in every environment.
- **Output guard false positive (found by me in live UI testing on 2026-11-02).** Claude's correct reply "about $222 left in your budget" was blocked as an invented price, so the app fell back to workflow mode. The guard was changed to accept simple arithmetic on grounded numbers and to remember tool results across turns; new numbers are still blocked. Regression tests added.
- **Training environment:** Claude first suggested removing Anaconda's MPICH package; the dry run showed it would downgrade Anaconda's Python (3.13 to 3.10) and break the project venv, so that was rejected and training was moved to a separate `mlxtrain` environment.
- I added my own explanatory comments to `backend/tools.py`.
- **Changes I asked for after testing the new UI (2026-11-03):** long paragraph replies were changed to short bullet replies; product names in quotes were too short ("Desert Sand" became "Desert Sand Porcelain Tile") and the same wording issues were fixed everywhere (m², no rule codes or "n/a" shown to customers); colours changed from the mockup's green/gold to Nabina's black, white and blue; all three columns made full height; square photos; a fixed 7 x 4 tile close-up grid; smaller suggestion buttons; the PDF button now creates the quote directly instead of going through the chat.
- **Room preview:** Claude explained it would need an image-AI model. I asked Mr Eulius, who said it isn't required and must not be presented as a finished AI feature. I first kept it as a labelled demo button, then removed all non-working buttons so the page only shows features that work.
- **LoRA not retrained** after the catalog changes: discussed with Claude and decided against it, because the adapter handles understanding, not prices (see `RESULTS.md`).
- The "is the improvement practically meaningful?" text in `reports/model_comparison.md` was drafted by Claude from my real comparison numbers and reviewed by me; it states the weaknesses (unfair intent metric, new objection failure).

## 6. How outputs were verified
- Unit and integration tests (`pytest`): tools, gateway failure handling, API, RAG, agent guardrails, dataset quality. Results in `RESULTS.md`.
- Independent recomputation of the assessment's calculator example (40 m2, 60x60, 4 per box, 10% gives 31 boxes, $1,383.84).
- The evaluation suite was run in both offline and Claude modes; failures are reported, not hidden.
- Model training and baseline-vs-adapted evaluation were executed on my own machine; logs are saved in `training/logs/` and `training/results/`.
- I read each file with Claude's explanations and can explain the design choices in the defense.
